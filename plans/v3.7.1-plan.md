## New Techniques for v3.7.1

### Verified against requirements:
- ✅ **Never interrupts humans** — passive collection, no visible UI
- ✅ **Blocks vision-based AIs** — works against DOM-level AND screenshot-based agents
- ✅ **Works in real websites** — used by Cloudflare, DataDome, Akamai, HUMAN Security

---

### TIER 1: HIGH IMPACT, EASY TO IMPLEMENT

#### 1. Font Enumeration Fingerprint
**Research basis**: Cloudflare, reCAPTCHA v3, all major anti-bot systems check font count. Headless browsers have ~5-15 fonts. Real user machines have 50-200+.
**Implementation**: 
- Client: `document.fonts.ready` → enumerate font faces, count unique families
- Server: Flag if font count < 15 (threshold calibrated for headless)
**Why it works**: Even sophisticated anti-detect browsers struggle to spoof 100+ realistic fonts. VLM agents can't fake this because they inherit the headless environment.

#### 2. Page Visibility / Focus Tracking
**Research basis**: Pydoll, HUMAN Security, Roundtable Research — real users tab-switch, blur windows, have idle periods. Bots maintain 100% continuous focus.
**Implementation**:
- Client: Track `document.visibilityState`, `window.onblur`, `window.onfocus` events
- Server: Flag if zero blur/focus events during entire session OR visibilityState never "hidden"
**Why it works**: VLM agents (Claude Computer Use, etc.) run in a fixed browser window and never alt-tab. Zero focus changes = automation signal.

#### 3. Canvas Fingerprint Collection (not just jammer)
**Research basis**: Standard fingerprinting technique used by FingerprintJS, reCAPTCHA, Cloudflare. Headless Chrome produces consistent canvas hashes; real GPUs produce unique ones.
**Implementation**:
- Client: Render text + shapes on a 2D canvas, collect the resulting pixel hash (toDataURL or getImageData hash)
- Server: Send hash as part of automation signals — even without a DB of known bots, identical canvas hashes across sessions from the same IP is suspicious
**Why it works**: Even when bots patch navigator.webdriver and WebGL, canvas rendering differences in headless mode persist.

#### 4. Browser Feature Coherence Matrix
**Research basis**: FP-Inconsistent (IMC 2025) — cross-attribute consistency reduced bot evasion by 45-48%. DataDome uses ML on feature coherence.
**Implementation**: Server-side cross-checks:
- Screen resolution 800×600 + UA claims latest Mac → mismatch (+40 pts)
- `languages[0]` locale doesn't match timezone → mismatch (+25 pts)
- Platform says "Win32" but plugins.length === 0 → unlikely (+25 pts)
- WebGL renderer contains "ANGLE" but `chrome` object is missing → impossible (+80 pts)
**Why it works**: Creating perfectly consistent fingerprints across 10+ browser attributes is exponentially harder than passing individual checks.

#### 5. Chromium Feature Depth Validation
**Research basis**: Cloudflare, headless detection research. Real Chrome has `chrome.csi`, `chrome.loadTimes`, deep `chrome.runtime` API. Headless/Puppeteer have partial stubs.
**Implementation**:
- Client: Check `chrome.runtime`, `chrome.csi`, `chrome.loadTimes` existence and depth
- Send as boolean signals
**Why it works**: Anti-detect browsers patch surface-level features but miss deeper API members.

### TIER 2: MEDIUM IMPACT, MODERATE COMPLEXITY

#### 6. Scroll Momentum Analysis
**Research basis**: DataDome, Akamai, Pydoll — human scrolling has momentum, deceleration, and burst patterns. Bot scrolling uses `window.scrollTo()` = instant discrete jumps.
**Implementation**:
- Client: Track scroll events with position + timestamp
- Server: Analyze scroll momentum (acceleration/deceleration), look for "instant teleport" scrolls
**Why it works**: Even sophisticated bots using Playwright scroll instantly. Human scroll via wheel/trackpad produces 30+ incremental events with physical momentum.

#### 7. Event Sequence Validation (Click Chain Integrity)
**Research basis**: Pydoll behavioral fingerprinting — real clicks: `pointerdown→mousedown→pointerup→mouseup→click` with preceding movement. Bots often dispatch bare click().
**Implementation**:
- Client: Track the last 10 event types and their ordering before each click
- Server: If click() is received without preceding pointerdown/mousedown events or movement, flag it
**Why it works**: VLM agents (Claude Computer Use, GPT-4V) often use CDP's `Input.dispatchMouseEvent` which skips intermediate pointer events, producing out-of-order or incomplete event chains.

#### 8. Keystroke Dynamics (Typing Rhythm Analysis)
**Research basis**: BeCAPTCHA-type (2023) — 99.98% accuracy via keystroke biometrics. Human typing has variable dwell/hold times, natural pauses, error corrections. Bots paste or type uniformly.
**Implementation**:
- Client: Track keydown→keyup duration and inter-key intervals per input field
- Server: Low variance in timing (σ < threshold) = keyboard emulator signal
**Why it works**: VLM agents use CDP `Input.dispatchKeyEvent` with programmatic timing (uniform intervals). Humans have 40-200ms variance per key. This is physiologically impossible to fake perfectly without a real HID device.

#### 9. Timezone vs. Language Consistency Check
**Research basis**: FP-Inconsistent paper, Cloudflare bot management — mismatched timezone+language+IP geography is a strong signal.
**Implementation**:
- Client: Send `Intl.DateTimeFormat().resolvedOptions().timeZone` and `navigator.languages[0]` 
- Server: Check if language is plausible for the timezone (e.g., `en-US` with `Asia/Tokyo` = mismatch)
**Why it works**: Bots on cheap proxies often misconfigure timezone/language pairs.

### TIER 3: LOWER PRIORITY (for future releases)

#### 10. AudioContext Fingerprint
**Research basis**: FingerprintJS, reCAPTCHA — AudioContext produces unique hardware-dependent output. Headless browsers produce different/shorter output.
**Why defer**: Complex cross-browser compatibility. Headless Chrome's AudioContext fingerprint is becoming more realistic.

#### 11. WebRTC IP Leak Detection
**Research basis**: Standard anti-bot + anti-fingerprinting signal.
**Why defer**: Requires server-side IP knowledge. Adds complexity. The current hook doesn't have access to the request IP easily.

#### 12. Proof-of-Work Client Challenge
**Research basis**: Cloudflare Turnstile uses proof-of-work. Invisible to humans, costly for bots.
**Why defer**: Adds client-side computation (~50-200ms). Could affect mobile battery. Needs careful threshold calibration.

## What We WON'T Do (Anti-patterns for our requirements)

| Technique | Why Not |
|---|---|
| CAPTCHA / Turnstile integration | Interrupts humans. AI solvers now achieve 90%+ accuracy. |
| IP reputation / ASN blocking | Requires external data, false positives on shared IPs. |
| Behavioral ML model training | Requires millions of labeled sessions. Out of scope for a zero-dep library. |
| TLS ClientHello modification | Not possible from application-layer JS. Requires reverse proxy/CDN. |
| Session recording / heatmaps | Privacy-invasive, heavy data transfer. |

## Risk Mitigation

| Risk | Mitigation |
|---|---|
| Font enumeration could be slow on some browsers | Add 500ms timeout, skip if fonts not ready |
| Page visibility might not be available in all contexts | Graceful fallback if APIs missing |
| Canvas fingerprint could vary per browser version | Use as supporting signal, never standalone block |
| Coherence checks could false-positive on edge cases | All coherence scores use low partial weights (25-40 pts) |
| Keystroke dynamics requires text input fields | Only fires if key events exist; silent otherwise |
| Scroll momentum analysis requires scroll events | Only fires if scroll data exists |
| Event sequence validation requires pointer events | Only fires if sequence data exists |
